# Mail CLI Go / Rust 重构评估

## 结论

- 当前阶段不建议立即重构为 Go 或 Rust。
- 建议先在 Python 继续稳定协议能力（OAuth2、HTML/多附件、更多测试）。
- 当满足以下条件时再启动重构：
  - 每月活跃用户持续增长并出现明显性能瓶颈；
  - 需要单文件静态分发（企业桌面场景）；
  - Python 依赖与运行时维护成本显著高于重写成本。

## 对比

### Go

- 优点：发布简单、并发与网络 I/O 体验好、生态成熟。
- 风险：MIME/IMAP 细节需要重新验证；现有 Python 测试资产不可直接复用。

### Rust

- 优点：性能与内存安全上限高，适合长期内核化。
- 风险：开发门槛高，协议迭代速度会下降，社区贡献门槛更高。

## 推荐路径

1. 保持 Python 为主实现，继续迭代到 v0.2。
2. 抽离协议核心接口（folder/message/flag/template），保证语言无关。
3. 以 Go 做一个 PoC（仅 `envelope list` + `message send`）评估迁移成本。
4. 仅当 PoC 在分发体验和维护成本上显著优于 Python 再进入正式重构。
